## 一、本次会话做了什么（一句话）

设计了一个**轻量 Transformer+Mamba 混合的通用运控模型**，历经架构 v1→v4 四版演进，最终确定为：**Mamba 做 world model 动力学预测器 + LeJEPA 的 SIGReg 防坍塌正则化 + 门控 attention 做技能切换 + MLP 解码高频动作**，并确立了"先借 TD-MPC2 训练栈 + Mamba 骨干跑通基线，再换 LeJEPA 风格对比增量"的务实三步走实现路线。

## 三、架构 v1→v4 演进脉络（理解当前状态必读）

| 版本 | 核心变化 | 关键判断 |
|---|---|---|
| **v1** | 初版：Mamba 慢通路 + 门控 attention + MLP action head，三通路分工 | 直觉性分工，参数预算不准（误报 1.2M） |
| **v2** | 深化：理论论证(SSM↔慢流形、attention↔离散检索)、张量化、修正参数(实为 ~2.5M)、有状态 PPO 适配 | max effort 重写，诚实修正参数估算错误 |
| **v3** | 训练范式改为 **World-Model 路线(TD-MPC2 风格)** 为主，直接 policy+PPO 降为备选 | 把 Mamba 有状态需求收敛到 world model 内，避开 off-policy 冲突 |
| **v4(当前)** | world model 正则化从 TD-MPC2 的"重构+KL"改为 **LeJEPA 的 SIGReg 为主**，TD-MPC2 降为备选；确立**务实三步走** | LeJEPA 无 EMA 与 Mamba 梯度干净契合；但补齐 LeJEPA 六类不足，先 TD-MPC2 栈兜底 |

**演进逻辑主线**：每版都是发现"前一版的结构性张力"后用更干净的结构化解——v3 把"有状态 Mamba vs off-policy"化解为"Mamba 进 world model(监督)、policy 无状态"；v4 把"world model 用什么正则化"选定为 LeJEPA，但用三步走平衡其工程风险。

## 四、关键决策与依据（这些是"为什么"，接续时务必保持一致）

### 4.1 为什么是混合架构(Mamba+attention+MLP)，不是纯一种

- **Mamba**：SSM 的 A 矩阵特征值对应多时间常数，天然承载技能身份/相位等慢变量（SFA 慢流形理论）。
- **门控 cross-attention**：技能切换是离散事件+远端依赖+多模态对齐，正是 attention 强、SSM 弱（associative recall 短板）的地方。
- **MLP action head**：高频解码，延迟最低。
- 职责正交、参数不重叠。详见主文档 §2、§6。

### 4.2 为什么走 World-Model 路线，而非直接 policy

- **核心矛盾**：Mamba 有状态 vs off-policy 随机采样天然冲突（buffer 随机抽取摧毁状态连续性，旧策略 h_t 喂新策略构成分布外状态）。
- **化解**：Mamba 进 world model 做监督预测（按轨迹采样，无冲突），policy 保持无状态可接任意 off-policy。这是结构变换绕开矛盾，非工程缓解。详见主文档 §7.1。

### 4.3 为什么 world model 选 LeJEPA(SIGReg) 为主、TD-MPC2 备选

**决定性理由**：LeJEPA 消除了 EMA/stop-gradient/teacher-student，使 Mamba 有状态 scan 的梯度路径干净——这是 TD-MPC2(靠重构)和 Dreamer(RSSM+target encoder EMA)都不具备的。加上 Sub-JEPA 子空间正则化与本方案 §2.1 慢流形理论同源。详见主文档 §7.4。

**但 LeJEPA 有六类不足**(§7.4.1)：精度 gap(无重构)、规划性不足(RC-aux)、足式高动态未验证、action-conditioned 需改造、超参无足式先例、生态成熟度低。因此不一上来全押，走三步走。

### 4.4 为什么"先 TD-MPC2 栈 + Mamba 骨干"跑通基线

- 借 TD-MPC2 的**训练范式**(off-policy actor-critic + MPC、replay、想象 rollout、sim-to-real)，**不借其 Transformer 骨干**。
- **Mamba 始终在 world model 动力学预测器位置，从不缺席**——若照搬 TD-MPC2 的 Transformer 骨干，Mamba 被架空，退化成纯 TD-MPC2。这是最易混淆的点，务必记住。
- 第 1 步是"TD-MPC2 栈驱动 Mamba world model"，第 2 步是"同栈换 LeJEPA 正则化"。两步差异只在 world model 正则化方式（重构+KL vs SIGReg）。

### 4.5 硬件约束如何影响选型

- 用户硬件：中高端 GPU(3090/4090)，**并行数受限**。
- 这使 FlashSAC 的"快"(依赖 1024 并行)打折扣；但 world model 的"想象 rollout"用算力换数据，**恰好对冲并行短板**——这是选 World-Model 路线的隐藏收益。
- 训练代价详见上次会话讨论（数据非瓶颈、阶段一算力友好、阶段二算力为瓶颈但可行、单卡 1~2 周含调试）。

## 六、未决问题（接续时优先关注）

### 6.1 骨架代码尚未对齐 v4
`hybrid_loco_skeleton.py` 的 `WorldModel` 类目前是 v3 的 TD-MPC2 重构式风格（Decoder 预测观测），**未加 SIGReg + PhysHead**。下一步应改成**双模式可切换**：
- 模式 A（第 1 步）：重构式（Decoder 预测观测 + KL），对应 TD-MPC2 栈
- 模式 B（第 2 步）：LeJEPA 式（预测 latent + SIGReg + PhysHead）
- 共享 Mamba 预测器骨干，仅正则化头切换。

### 6.2 LeJEPA 在足式高动态下未验证（最大风险）
LeWorldModel 只在 2D/3D 平滑控制验证。硬接触、冲击、支撑/摆动相切换是未知数。对策是接触条件预测器（LeJEPA-Loco 设想，未验证）或退回 TD-MPC2。**需要实测验证**。

### 6.3 精度 gap 未实测
LeJEPA 无重构可能丢关节级精度，靠 PhysHead 物理量重构缓解。但 PhysHead 的 λ_rec 与 λ_sig 权衡、重构精度是否达 mm 级，**未实测**。probing 验证是关键检验手段。

### 6.4 训练代价是估算非实测
上次会话给的代价（单卡 1~2 周、数据 1M~10M）是基于架构参数的估算，非实际跑通数据。第 1 步跑通后需校准。

### 6.5 action-conditioned 动力学改造
LeJEPA 原始"视图预测视图"不带 action，第 2 步要改成 `ẑ_{t+1}=Pred(z_t, a_t)`。Action-Conditioned JEPA(心脏那篇)证明可行但仅心脏验证过。
