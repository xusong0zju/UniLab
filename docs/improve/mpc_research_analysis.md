## 0. 调研资料概览

资料含 `人形机器人MPC开源调研.md`(451行) + crocoddyl 源码(devel分支).
调研核心问题: 多接触 MPC 中, 接触力是"估计"还是"求解"?

**调研核心结论(§4, §6)**:
- 接触力 λ 在 MPC 内是**优化变量/对偶变量**, 通过 KKT 系统**求解**, 非传感器估计.
- KKT 系统: `[M, Jcᵀ; Jc, 0][q̈; -λ] = [τ-h(q,v); -a₀]`, 选定 τ + 接触约束后, λ 是必然结果.
- Pinocchio 的 `forwardDynamics(model, data, tau, Jc, a0, damping)` 直接解出 `data.lambda_c`(已核验可用).
- 主动接触(有驱动, 如腿蹬地)τ 间接决定 λ; 被动接触(无驱动, 如背贴地)λ 是外力.

## 1. 对我们三个设计决策的逐个审视

### 1.1 决策1: 接触点检测(启发式)→ 该不该改成求解?

**我们当前**: `wrist_z<0.10` 判手接触, `foot_contact_sensor` 判脚接触 → 切换 GC 基准.

**调研指出**: 接触力可由 `forwardDynamics` 求解, λ 大的点是真支撑点.

**关键区别(厘清)**: `forwardDynamics` 求 λ 需要**先知道哪些点在接触**(给 Jc).
它不是"发现接触点", 而是"给定接触约束后算接触力". 所以:
- **接触点检测**(哪些点着地)仍需要——启发式(contact sensor/高度)或互补约束(求解器自动发现)
- **接触力大小**(各点承重多少)可由 forwardDynamics 求解

**判断**: 部分借鉴. 接触点检测保持启发式(sim 里 contact sensor 可用).
**真正该借鉴的不是"检测方式", 而是"用求解的 λ 判断承重分配"**——
双脚都着地时, 哪只脚承重多(λ 大), 用这个区分主支撑脚(而非简单 c_foot=0.5).
但对当前二阶段判断(背+肘 vs 双脚), 启发式够用.

### 1.2 决策2: 二基准 GC 切换(w_pelvis/w_foot)→ 该不该改成 KKT/forwardDynamics?

**我们当前**: policy 输出 w∈[0,1], 在 g_pelvis 和 g_foot 间插值.

**调研的 KKT 方法**: `τ = PD + g(q)` 里, 若用 forwardDynamics 而非纯 RNEA,
接触约束自动让 τ 包含正确的接触力补偿——不需要手工切换 GC 基准.

**但根本路线差异**:
- 调研的 MPC/OCS2/Crocoddyl 是**离线/在线轨迹优化**(给定任务, 求解最优 τ 序列), 接触力是优化变量
- 我们是 **RL 训练**(policy 学策略), τ 由 policy 输出, GC 是前馈补偿
- RL 里接触由 MuJoCo 物理引擎**隐式处理**(和 DIAL-MPC 哲学C 类似), 不需要显式求解 λ

**关键洞察(§6.1b 主动vs被动接触对应我们的两阶段)**:
- 主动接触(脚, 有驱动): τ 间接决定 λ → forwardDynamics 可求解 → 但 RL 里 MuJoCo 已隐式处理
- 被动接触(背/肘, 无驱动): λ 是外力 → GC 用 pelvis 基准(背支撑躯干)

**判断**: 不颠覆, 可优化. RL + MuJoCo 隐式接触(哲学C)是合理路线, 不需要改成 MPC 的 KKT 求解.
二基准 GC 切换可用 forwardDynamics 的 λ 做更精确判断(而非纯启发式), 但对 sim 训练启发式够用.

### 1.3 决策3: 起身动作序列 → 调研的 impulse/make-break 处理

**调研 §6.2c**: 足式运动每步经历"摆动→触地→支撑→离地", 触地瞬间有**冲量/速度突变**,
用 `impulseDynamics` 处理(已核验 pin.impulseDynamics 可用).

**我们当前**: K1-K5 关键帧是静态姿态, 没考虑触地瞬间冲量. K3 腿蹬地触地时可能有速度突变.

**判断**: 补充, 不颠覆. BC 预热可不处理冲量(简化), RL 微调会修正. 真要精确可加 impulseDynamics.

## 2. 真正值得借鉴的(按优先级)

### 2.1 用 forwardDynamics 的 λ 做精确承重分配(中优先级)

当前 `gc_weight_align` reward 用 `c_foot = 接地脚数/2`(0/0.5/1), 粗糙. 可改成:
- 给定接触点(脚/肘), 调 `pin.forwardDynamics` 算 λ
- λ 大的脚 = 主支撑脚 → w_foot 更高
- 双脚 λ 接近 = 双支撑 → w_foot=0.5

但这对 sim 训练改善有限(MuJoCo 接触已隐式处理), 主要对真机有价值.

### 2.2 DIAL-MPC 的采样式探索(潜在借鉴, 若 RL 持续失败)

调研 §3.4: DIAL-MPC 是**采样式 MPC**(从分布采样多条轨迹选最优),
在 MuJoCo MJX/Brax 直接 rollout, 不显式建模接触, "不需要预定义接触序列".

对我们: RL 策略梯度探索可能不足以发现起身序列(已验证: 探索能动但确定性躺平).
DIAL-MPC 的采样式探索可能比策略梯度更有效——从分布采样多条起身轨迹, 选最优.
但这需要引入 DIAL-MPC 框架, 成本较高.

### 2.3 离线优化起身轨迹做 BC 数据(重要备选)

调研的 Crocoddyl/OCS2 能**离线优化**起身轨迹:
- 给定 K1-K5 关键帧 + 接触约束(背/肘/脚着地)
- 求解最优 τ 序列 + 接触力(含动力学一致)
- 作为 BC 预热数据, 比"手工关键帧插值"更物理一致(含接触力、动力学)

这是"MPC 生成参考轨迹 + RL 学习"的混合路线, 可能比纯 RL 更可靠.
若 RL 持续训不出起身, 这是首选 fallback.

### 2.4 contact-force 残差做 reward(低优先级)

Crocoddyl 的 `contact-force` 残差 `r = λ - λ*` 可约束接触力.
我们可加 reward: 惩罚接触力过大(保护关节)或约束 CoP 在支撑面内.
但当前起身训练瓶颈不在这里(瓶颈是 policy 学不到起身动作).

### 2.5 接触力作为状态(低优先级)

把求解的 λ 加入 obs, 让 policy 感知接触力(而非只看关节角/IMU).
可能帮 policy 判断"该用哪个基准起身". 但增加 obs 维度, 训练负担.

## 3. 颠覆 vs 补充 vs 无关(总表)

| 调研内容 | 对我们的影响 | 判断 |
|---------|------------|------|
| 接触力是求解非估计(§4,§6) | RL+MuJoCo 是隐式接触(哲学C), 不需要显式求解 | **不颠覆**(路线不同但合理) |
| forwardDynamics 求 λ(§6.2b) | 可用于精确承重分配, 但 sim 启发式够用 | **补充**(优化, 非必须) |
| 主动vs被动接触(§6.1b) | 对应我们的两阶段(脚主动/背被动) | **印证**(我们设计合理) |
| impulse/make-break(§6.2c) | BC 预热可不处理, RL 微调修正 | **补充**(细节) |
| KKT 系统替代 GC 切换 | RL 里 MuJoCo 已隐式处理接触, 不需 KKT | **不颠覆**(路线差异) |
| DIAL-MPC 采样式(§3.4) | 探索可能比策略梯度有效 | **潜在借鉴**(若 RL 持续失败) |
| 离线优化做 BC 数据(§2.3) | Crocoddyl 优化起身轨迹作为 BC | **重要备选**(首选 fallback) |
| contact-force 残差(§5.3) | 约束接触力, 但当前瓶颈不在这 | **无关**(暂不需要) |
| 接触力入 obs | 帮 policy 感知接触, 但增 obs 维度 | **低优先级** |

## 4. 对当前最痛痛点(RL 训不出起身)的直接帮助

当前最痛: **RL 训不出起身(policy 躺平)**. 调研对这个问题的帮助:

1. **DIAL-MPC 思路**(哲学C: 采样式 MPC 在物理引擎 rollout)——和我们 RL 类似,
   但 DIAL-MPC 是**采样式**(从分布采样多条轨迹选最优), 比策略梯度可能更有效探索起身序列.

2. **BC 预热数据来源**: 若纯 RL 探索不到起身, 可用 Crocoddyl/OCS2 **离线优化**起身轨迹
   (给定 K1-K5 + 接触约束, 求最优 τ), 作为 BC 数据. 比"手工关键帧插值"更物理一致.

3. **接触力作为状态**: 把求解的 λ 加入 obs, 让 policy 感知接触力.
   可能帮 policy 判断"该用哪个基准起身".

---

## 5. 结论与建议

**一句话**: 调研**没颠覆**我们的 RL+GC 路线(MuJoCo 隐式接触是合理的哲学C),
但给了两个重要备选:
1. 若 RL 持续失败, 用 Crocoddyl **离线优化**起身轨迹做 BC(首选 fallback)
2. DIAL-MPC 的**采样式探索**可能比策略梯度更适合发现起身序列(备选)

**当前应继续**: RL + 二基准GC + BC 预热(用关键帧), 把 Crocoddyl 离线优化作为 fallback.

**已核验可用的 Pinocchio 接口**:
- `pin.forwardDynamics(model, data, tau, Jc, a0, damping)` → data.lambda_c(接触力)
- `pin.impulseDynamics`(冲量, 触地瞬间)
- `pin.getKKTContactDynamicMatrixInverse`(KKT 逆, 用于导数)
